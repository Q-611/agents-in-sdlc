プロジェクトに小さな機能を追加しました。より大規模な変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot app は組織の既存の作業手順に沿って動作し、適切なものを適切な方法で構築できるようにします。このレッスンから、エージェント主導の開発プロセスに沿って進めます。Issue から新機能を作成し、コードが妥当で機能が期待どおりに動作することを確認して、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能のワークフローでは、同じセッションを使います。通常、ファイルの種類ごとに異なるセッションや PR を使いますが、ここでは主な概念に集中できるよう簡略化しています。

このレッスンでは、次の内容を学習します。

- GitHub Issue からエージェントセッションを開始する。
- **Plan** モードで要件を定義する。
- **Autopilot** モードで新しい機能を実装する。
- コードをレビューする。
- ブラウザーキャンバスで機能を手動で検証する。

機能の作業を続けながら、リポジトリの指示を更新し、既存の quality-checks スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが増えてきたため、利用者がカテゴリや発行元でゲームを絞り込めるようにします。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておく必要のある詳細があります。Plan モードで決定し、Autopilot に範囲を限定した実装を許可します。

## 背景

AI コーディングエージェントを開発ワークフローに加えても、基本は変わりません。むしろ、より重要になります。多くの開発者は、次のような流れで作業します。

1. 実装内容の詳細が記載された Issue を開きます。
2. 構築する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、ほとんどの場合は上記の流れを多少変更したものです。

この標準的なアプローチに従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューのプロセスを通るようにします。

## セッションモード

**セッションモード**によって、エージェントに与える自律性の程度を制御できます。プロンプトフィールドの下にあるドロップダウンで設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。エージェントが実行する前に、計画をレビューして承認します。
- **Autopilot**: エージェントは完全に自律的に作業し、入力を待たずにコードを書き、テストを実行し、反復します。

Plan モードで始めて計画をレビューし、その後 Autopilot で実装します。

## Issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリフォルダーを選択し、リポジトリ上部のナビゲーションで **Issues** を選択します。既存の Issue **Allow users to filter games by category and publisher** を開きます。テンプレートに含まれる Issue なので、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. Issue がセッションに添付されていることを確認し、モードセレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` の実行を依頼します。ターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH またはバージョンマネージャーの設定を確認し、アプリを完全に終了して再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## 絞り込み機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチを確認できます。Issue から開始したため、Copilot はすでに機能のリクエストをコンテキストとして持っています。次を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、計画を Issue の受け入れ条件と照らし合わせます。カテゴリと発行元による絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認します。複数のカテゴリをどう組み合わせるか、一致するゲームがない場合にどうなるかなど、不明確な動作について話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニットテスト、E2E テスト、型チェックを含めます。絞り込み機能の実装とテストに範囲を絞ります。品質ワークフローを終えてから PR を作成します。計画の修正は承認前に依頼し、後で検証するために Issue の URL と合意した明確化事項を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan** (または使用中のバージョンで同等のオプション) を選択します。承認しただけでモードが自動的に切り替わるとは限らないため、実際に選択されているモードを確認します。モード表示が **Autopilot** になっていることを確認します。

Copilot が実装を開始します。計画に沿って反復し、コードを生成してテストを実行します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係が不足している、またはポートが競合していると報告された場合は、セットアップの問題を解決してからチェック完了と判断します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、他のコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して問題がないか検証します。

1. **Changes** を開き、絞り込み機能の実装とテストを確認します。
2. 複数カテゴリや発行元の組み合わせも含め、結果を Issue と承認した明確化事項に照らし合わせます。変更が既存のリポジトリの指示に従っていることを確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの出力を確認します。スキップされたチェックは成功ではありません。
4. 実装を採用する前に失敗を解決し、該当するチェックを再実行します。Playwright の E2E 設定はビルドとプレビューを配信し、ローカルサーバーを再利用することがあります。テスト対象が前のレッスンではなく、この worktree に属するサーバーであることを確認します。

## 新機能を試す

コードに問題がないことを確認できました。次は、アプリを起動してブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを送信し、アプリを起動してブラウザーキャンバスで開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリを選択し、結果がカテゴリに一致することを確認します。絞り込みを解除してから発行元を選択し、結果が発行元に一致することを確認します。
4. カテゴリと発行元の絞り込みを組み合わせ、結果を Issue と承認した計画に照らし合わせます。複数カテゴリがサポートされる場合は、合意した組み合わせの動作を確認します。
5. 一致するゲームがない組み合わせを試し、空の状態を確認します。絞り込みを解除またはリセットし、一覧全体が戻ることを確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンに向けてセッションを保持する

絞り込みの PR はまだ作成またはマージしないでください。レッスン 4 から 8 まで同じセッション、worktree、ブランチを使います。次は絞り込みコードにカスタム指示を適用し、スキルと QA の改善を追加してから、レッスン 8 でまとめた PR を作成してマージします。開発サーバーを停止した後、セッションをそのままにしてもかまいません。次のレッスンで同じセッションに戻ります。
