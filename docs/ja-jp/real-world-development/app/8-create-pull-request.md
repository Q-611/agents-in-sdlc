フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストを1つのブランチに保存しました。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスの管理を任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントをいくつかの別々の PR に分けます。ワークショップを円滑に進めるため、フィルター機能と品質ワークフロー全体を1つのセッションとブランチで進め、そのすべての作業をこの PR にまとめました。

このレッスンでは、次の内容を学習します。

- Agent Merge の概要と、マージのライフサイクルを自動化する仕組みを学ぶ。
- 機能の PR 全体と検証の証拠を確認する。
- レビュー後にのみ Agent Merge を承認し、PR がマージされたことを確認する。

## シナリオ

フィルター機能のワークフロー全体を通じて、Copilot を使って機能の計画、実装、検証を行いました。Tailspin Toys は、マージの承認を開発者の管理下に置きながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするまでに必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要に応じたリベースなど、マージを妨げている問題に対処します。GitHub でマージが許可されると、プルリクエストをマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に無効になります。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge にその作業を任せることもできますが、コードの編集やマージには引き続き明示的な承認が必要です。マージを許可する前に、Agent Merge に許可する操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR プロセスを管理させます。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択し、プロセスを開始します。ドロップダウンで項目を選んだだけでは開始されません。

Agent Merge のプロセスが始まります。次の処理を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- Issue からセッションを開始した場合は、説明の本文で関連する Issue を参照します。
- ターゲットブランチへのリベースや、発生する可能性のあるマージ競合に対処します。
- CI を監視し、すべてのチェックが成功するようにします。
- 他の開発者や Copilot code review からのフィードバックがないか PR を監視し、コメントを解決するために変更を加えます。
- 必要に応じて、すべてのチェックが成功した後に PR を自動的にマージします。

すべてのチェックが成功したら、Agent Merge に PR のマージも任せましょう。

5. マージを許可する前に、PR の差分と検証の証拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のように明示して、エージェントにマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告された阻害要因を解決します。続行する前に、PR の状態が **Merged** であることを確認してください。マージの許可を有効にしたことやエージェントの実行中表示は、マージが完了した証拠ではありません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行前にそれらの阻害要因を解消してください。
