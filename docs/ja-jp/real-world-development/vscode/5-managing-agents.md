GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、その作業を自分のマシンでリアルタイムに確認できます。すべてのツール呼び出しやファイル編集を確認し、差分をインラインでレビューして、変更を個別に採用または破棄できます。エディターを離れずに、追加のプロンプトを送って会話を誘導し、作業を改善したり広げたりできます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集を確認して採用する。
- セッションの途中でエージェントに指示し、ハイコントラストモードにライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードも切り替えられるようにします。新しい会話を最初から始めるのではなく、既存のセッションに追加の指示を出して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べるファイル、実行するコマンド、提案する編集など、各ステップを確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業してもらいます。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用許可を求める場合 (たとえばターミナルコマンドの実行など)、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけ承認してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に、行った変更をまとめるメッセージが表示されます。

## エージェントにライトモードを依頼する

ハイコントラストモードができたので、同じ会話でライトモードの切り替え機能も追加します。同じチャットセッションを続けるため、エージェントは以前に変更したコンポーネントやスタイルの方針、local storage を使った実装方法などのコンテキストを保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはこれまでの変更を調べ、ライトモード用の追加を提案します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば好まない方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送信します。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます (例: 「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」) 、方向を修正できます (例: 「トグルを 3 つに増やさず、既存の設定パネルにライトモードを追加する」) 、または範囲を広げられます (例: 「両方のトグルにキーボードショートカットも追加する」) 。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストの更新が表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視して方向付けしました。各ファイル編集を確認し、変更を採用または破棄して、コンテキストを保ったまま追加のプロンプトで作業を広げました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に採用または破棄する。
- 追加プロンプトで実行中のセッションを方向付けする。
